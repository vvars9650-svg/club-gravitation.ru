# AGENTS.md — ГРАВИТАЦИЯ / правила Codex

Эти правила действуют для всего репозитория, если конкретная задача явно не задаёт более узкое или более строгое правило.

## 1. Локальное выполнение

- Codex самостоятельно выполняет через встроенный терминал все обычные безопасные локальные действия внутри рабочего репозитория: `git status`, `git diff`, `git log`, поиск по файлам, создание worktree/веток, запуск dev-server, build, тесты, lint/checks, подготовку screenshots и другие необходимые диагностические команды.
- Не просить Влада вручную открывать PowerShell/Terminal и выполнять команды, которые Codex способен выполнить сам.
- Ручное участие Влада требуется только для пароля/2FA, UAC или системного подтверждения, секрета, необратимого действия, доступа за пределы разрешённой рабочей области либо явного разрешения на внешнюю систему.

## 2. Безопасность рабочей копии

- Перед изменениями проверить фактический repo, branch, HEAD и `git status`.
- Не считать путь с другого компьютера актуальным автоматически.
- Не перезаписывать, не reset/discard/stash и не включать в свои коммиты неизвестные или чужие локальные изменения.
- Если основная рабочая копия грязная и изменения не относятся к задаче, предпочитать отдельный `git worktree` от подтверждённого baseline.
- Не редактировать одни и те же файлы параллельно в нескольких worktree без явного согласования.

## 3. Commit / push / deploy

- Не выполнять commit, push, merge, deploy, DNS/hosting/cloud mutation или иные внешние изменения, если текущая задача явно этого не разрешает.
- Различать состояния: выполнено локально → закоммичено → pushed в GitHub → CI PASS → TEST deployed/checked → production.
- PROD, main DNS и реальный intake не изменять без отдельного явного разрешения.

## 4. Встроенный браузер

Для frontend/visual задач Codex использует встроенный браузер сам, а не перекладывает навигацию на Влада.

Рабочий публичный набор страниц, когда они относятся к задаче:
- `/`
- `/about/`
- `/events/`
- `/founders/`
- `/apply/`

`/admin-test/` считать отдельным техническим контуром и не смешивать с визуальной сессией публичного сайта без необходимости.

- Для локальной разработки Codex сам запускает dev-server и открывает соответствующие localhost URL.
- Для проверки TEST использовать `https://test.club-gravitation.ru/` и нужные публичные маршруты.
- Не закрывать рабочие вкладки/браузерную сессию без необходимости; сохранять состояние для продолжения работы и аннотаций.

## 5. Стандарт visual QA

Если задача касается responsive/public frontend и не задаёт другую матрицу, использовать как минимум:
- desktop: `1440×900`, DPR 1;
- desktop HiDPI: `1440×900`, DPR 2;
- mobile: `390×844`, DPR 3;
- narrow mobile: `360×800`, DPR 3.

Tablet проверять как regression smoke, если задача не включает отдельный tablet-design pass.

Для визуальных задач:
- проверять horizontal overflow, clipping, overlays, console/network ошибки;
- делать screenshots ключевых состояний;
- использовать browser/annotation workflow для точечных правок после первого прохода.

## 6. Публичная безопасность

- `/apply/` должен оставаться `PUBLIC_BLOCKED`, пока конкретная утверждённая задача не меняет этот gate.
- Не подключать TEST Admin config, backend/private assets, секреты или реальные персональные данные к public artifact.
- Не включать реальный PROD intake/photo collection без отдельного legal/technical gate.

## 7. HANDOFF

В конце самостоятельной задачи вернуть кратко:
- что сделано;
- где результат: worktree/branch/HEAD/commit/PR/file;
- какие файлы изменены;
- что проверено и с каким итогом;
- что осталось;
- были ли локальные изменения вне задачи и остались ли они нетронутыми;
- требуются ли действия Влада или управляющего чата.

## 8. Контекст и repo Skills

- Один самостоятельный крупный этап вести в одном Codex-чате. Продолжать текущий чат, пока накопленный контекст помогает той же задаче; после закрытия этапа или при тяжёлом/шумном контексте переходить в новый чат с коротким HANDOFF без истории попыток.
- Не использовать фиксированный token threshold как формальный gate для нового чата.
- `AGENTS.md` держать короткой картой постоянных правил. Повторяемые подробные процедуры хранить как repo Skills в `.agents/skills`; Codex использует соответствующий Skill только когда задача ему соответствует.
- Базовые repo Skills:
  - `gravitation-release` — controlled build/deploy/live-smoke/rollback;
  - `gravitation-handoff` — компактный перенос контекста;
  - `gravitation-visual-qa` — public frontend visual/responsive QA.
- Browser/MCP/subagents использовать только когда они реально нужны задаче; не запускать тяжёлые инструменты или параллельных агентов для маленькой последовательной работы.
- Для механических задач выбирать минимально достаточную модель/effort; повышать уровень только при сложности, риске, неоднозначности или повторной неудаче.
